## Findings

### [CRITICAL] The PR is not cleanly scoped to a single task
This PR is titled for `form4-cross-sectional-sale-pressure`, but it also modifies a second task:
- `tasks/13f-amendment-aware-crowding/*`

A task PR should be self-contained. Mixing two tasks in one PR makes review, provenance, and merge decisions unnecessarily noisy.

### [MAJOR] The verifier has the same brittle reward-writing pattern
`tests/test.sh` still uses the fragile `$?` pattern after the main `uvx ... pytest ...` invocation. This should be rewritten as `if uvx ... pytest ...; then ... else ... fi`.

### [MAJOR] The task appears heavily reference-data-driven
This task uses a large `/tests/reference_data/*` package and many exact equality checks against those reference outputs. That can be valid, but it weakens benchmark elegance because success depends on reproducing a fixed oracle artifact very closely, rather than satisfying a more principled set of invariants.

### [MINOR] Solution strategy may be overly oracle-like
The reference solution appears to rely on pre-provided XML ownership files inside `solution/`, rather than reconstructing everything from PDFs inside the solve flow itself. That is okay for oracle generation, but it means the task’s true difficulty for agents is PDF extraction + normalization, while the oracle bypasses part of that burden.

## What is good
- The task contract is detailed.
- The outputs are well-structured.
- The analytics layer is richer than a plain extraction task.

## What should change
1. Split the unrelated `13f-amendment-aware-crowding` changes into a separate PR.
2. Fix verifier reward handling.
3. Clarify and justify the oracle-generation path relative to the actual agent task.
4. Consider whether exact reference matching is too strong a dependency for a hard benchmark task.
