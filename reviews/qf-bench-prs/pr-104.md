### D. Evaluation Criteria & Grading Reliability — 4/10
**[MAJOR] Verifier reward handling is reportedly still brittle**  
The earlier review notes indicate `tests/test.sh` still uses the fragile `$?` pattern rather than an explicit `if ...; then ... else ... fi` wrapper.

Suggested fix: rewrite the shell wrapper in explicit form.

**[MAJOR] The task appears heavily reference-data-driven**  
The prior notes indicate reliance on a large `/tests/reference_data/*` package and many exact reference-output checks. That can be valid, but it makes success depend heavily on reproducing a fixed artifact surface.

Suggested fix: clarify whether exact reference matching is truly the intended benchmark objective.

**[MINOR] The oracle path may bypass part of the real agent burden**  
The prior notes indicate the reference solution may rely on pre-provided structured ownership files rather than reconstructing everything from PDFs within the solve flow. That is acceptable for oracle generation, but it creates some distance between the benchmark's apparent difficulty and the oracle's path.

Suggested fix: explain and justify that oracle-generation path clearly.
