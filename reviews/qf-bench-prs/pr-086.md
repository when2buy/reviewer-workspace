### What This PR Does (Plain Language)
This PR adds a portfolio-risk benchmark task built around DCC-GARCH modeling, portfolio VaR / ES estimation, filtered historical simulation, and backtesting diagnostics. In plain terms, the agent has to implement a fairly rich multi-asset volatility and risk-measure pipeline.

Review focus: the important questions here are whether the task really earns a hard label, whether the grading behavior is reliable, and whether the verifier philosophy is internally consistent.

### A. Structural Completeness — 8/10
This is one of the financially richer tasks in the batch. The modeling depth is meaningfully above the simpler analytics and migration exercises.

### B. Task Contract & Determinism — 7/10
The task appears directionally strong, but the grading style seems to mix different philosophies, which makes it harder to judge exactly what kind of correctness is being rewarded.

### C. Difficulty Calibration & Model Signal — 6/10
**[MAJOR] The task could plausibly be hard, but the PR still needs stronger evidence**  
Among this batch, this is one of the few tasks where a `hard` label feels plausible. But “plausible” is not enough. I still want explicit evidence: oracle behavior, weaker-model failure, frontier-model behavior, and a short explanation of where the practical difficulty actually comes from.

Suggested fix: add stronger empirical validation evidence for the claimed difficulty.

### D. Evaluation Criteria & Grading Reliability — 4/10
**[MAJOR] The verifier shell pattern is still brittle**  
The earlier review notes indicate `tests/test.sh` still uses the `$?` pattern after the main `pytest` invocation rather than wrapping the command directly in `if ...; then ... else ... fi`.

Suggested fix: rewrite the shell wrapper in explicit `if ...; then ... else ... fi` form.

**[MINOR] The verifier philosophy looks mixed**  
The task reportedly combines plausibility-band checks, pinned oracle moments, and fixed structural properties. That is not necessarily wrong, but it is somewhat awkward for a hard benchmark because it is not always clear whether the task is rewarding exact replication or financially valid approximation.

Suggested fix: make the grading philosophy more internally consistent.

### Summary
This task has real financial substance, and I can believe it might deserve a hard label. But the current PR still needs stronger supporting evidence, and the verifier handling should be tightened before merge.
