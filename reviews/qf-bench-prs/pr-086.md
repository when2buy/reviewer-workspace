## Findings

### [MAJOR] The task is financially richer, but the verifier still mixes plausibility-band checks with pinned oracle moments
This one is materially better than the simpler tasks. It has univariate GARCH, DCC estimation, VaR / ES, FHS via stationary bootstrap, and Kupiec / Christoffersen backtests.

But the verifier still partially relies on:
- broad plausibility ranges,
- pinned means for FHS VaR/ES,
- fixed expected structural properties.

For a hard task, I would want confidence that the task separates genuine model implementation quality, not just approximate shape-matching.

### [MAJOR] Verifier shell pattern is still wrong
Again, `tests/test.sh` uses the brittle `$?` pattern after `uvx ... pytest ...`.

### [MAJOR] Difficulty label may be plausible, but evidence matters
Among this batch, this is one of the few that actually could deserve `hard`. But I still want empirical evidence: oracle pass, weak-model failure, frontier behavior, and why this is hard in practice rather than just mathematically long.

### [MINOR] Mixed benchmark signal: some tests are too permissive, some are strongly pinned
A few checks are broad range checks, while others pin exact oracle moments for the FHS outputs. That combination is slightly awkward.

## What is good
- Substantive financial content.
- Good statefulness and modeling depth.
- Better benchmark flavor than the easier data/transformation tasks.

## What should change
1. Fix verifier reward handling.
2. Strengthen the PR’s evidence for `hard`.
3. Revisit verifier philosophy for consistency.
