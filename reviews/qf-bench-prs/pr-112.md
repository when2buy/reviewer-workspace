## Summary
PR #112 adds a clear, deterministic medium-difficulty task around EWMA covariance, portfolio risk decomposition, and parametric VaR. The financial content is good, the output contract is precise, and the task likely separates strong from weak agents on numerical implementation.

The main problem is benchmark leakage: `tests/test_outputs.py` contains the full canonical computation, including the exact EWMA recursion, use of `estimation_window_days`, and the VaR formula. There is also the recurring fragile reward-writing pattern in `tests/test.sh`.

## Findings

### [MAJOR] The verifier leaks the full oracle logic
`tests/test_outputs.py` does not just check outputs, it fully re-derives the expected answer from visible inputs:
- loads `params.json`
- applies `estimation_window_days`
- runs the exact EWMA recursion
- computes portfolio variance, vol, marginal risk, component risk, % contribution
- computes VaR with `norm.ppf(conf_level)`

That makes the task easy to shortcut.

### [MAJOR] Tests reveal task-specific implementation choices that the instruction frames as reasoning work
The instruction says the agent should compare against standard references and determine correct choices, but the test file explicitly answers those questions.

### [MINOR] `tests/test.sh` uses the brittle `$?` reward pattern
This script still uses the fragile `$?` pattern after the main `uvx ... pytest ...` invocation.

### [MINOR] The solution is very close to the verifier logic
The oracle solution is nearly identical to the visible canonical recomputation in the test. That is another sign the task is currently too easy to reverse-engineer from verifier artifacts.

## What should change
1. Hide or reduce oracle leakage in the verifier.
2. Preserve the “debugging” nature of the task by avoiding tests that give away the intended math.
3. Fix reward handling in `tests/test.sh`.
4. Optionally strengthen anti-cheating posture.

## Verdict
**REQUEST CHANGES**
