### What This PR Does (Plain Language)
This PR adds a benchmark task where an agent must estimate an EWMA covariance matrix from ETF return data, decompose portfolio risk into marginal and component contributions, and compute parametric Value at Risk. In plain terms, the agent has to turn raw return history and portfolio weights into a complete risk report.

Review focus: the main benchmark risk here is oracle leakage through the verifier. This kind of task is supposed to test whether an agent can correctly implement the EWMA recursion and portfolio-risk math. If the visible test file re-derives the exact intended solution from the raw inputs, a large part of that reasoning burden is handed back by the benchmark itself.

### C. Reasoning & Benchmark Signal — 6/10
The underlying task is useful. Correctly implementing EWMA weighting, covariance estimation, and risk decomposition does test genuine numerical reasoning.

The weakness is that the visible verifier appears to answer too much of the intended reasoning path, which lowers the real benchmark burden.

### D. Evaluation Criteria & Verifier Quality — 3/10
**[MAJOR] The verifier exposes the full canonical computation path**  
File: `tasks/ewma-portfolio-risk-decomposition/tests/test_outputs.py`

The test file does not just validate outputs. It visibly reconstructs the intended math from the raw inputs, including the EWMA recursion, the estimation window application, the portfolio variance path, and the downstream risk decomposition logic.

That weakens contamination resistance and makes the task easier to shortcut by reading verifier logic instead of independently reasoning through the implementation.

Suggested fix: move more of the canonical recomputation behind a hidden reference or reduce the visible test logic to invariants and contract checks.

**[MINOR] The verifier likely over-specifies implementation choices that the instruction frames as analytical work**  
Files: `instruction.md`, `tests/test_outputs.py`

When the visible tests answer the exact numerical pathway, the task becomes less about risk-model implementation and more about matching the benchmark author's chosen script.

Suggested fix: preserve determinism, but expose less of the oracle path in the public verifier.
