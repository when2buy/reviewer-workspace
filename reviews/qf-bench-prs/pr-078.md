### What This PR Does (Plain Language)
This PR adds an FX benchmark task where an agent must build and evaluate a carry-trade backtest, including ranking currencies, applying lagged signals, handling quote-convention details, incorporating transaction costs, and splitting results by regime. In plain terms, the agent has to turn FX market inputs into a strategy backtest and summary analytics.

Review focus: the key questions here are difficulty calibration, benchmark signal quality, and whether the task is testing genuine FX reasoning rather than a heavily scaffolded implementation exercise.

### C. Difficulty Calibration & Model Signal — 4/10
**[MAJOR] This does not look convincingly hard**  
The task has real domain details, including FX quote conventions, lagged ranking, transaction-cost drag, and regime splits. But the overall workflow still appears heavily scaffolded, and the review notes indicate the tests point at several intended traps quite directly.

Suggested fix: either downgrade the difficulty label or provide stronger empirical evidence that this genuinely behaves like a hard task.

**[MAJOR] Hardcoding / overfitting resistance appears limited**  
The schema is fixed and many exact values are checked. That makes the task easier to optimize toward a known target surface.

Suggested fix: improve validation evidence and consider whether more invariant-style checks would better support the claimed difficulty.

### D. Evaluation Criteria & Grading Reliability — 7/10
One good point here: the verifier shell is better engineered than several comparable tasks. The earlier review notes indicate reward writing is deterministic rather than relying on a brittle pattern.

**[MINOR] Output path convention is a little inconsistent**  
Writing to `/app/submission/results.json` instead of the more common `/app/output/...` is not wrong, but it adds avoidable inconsistency across tasks.

### Summary
This is a real FX task, not a toy. But I am not convinced by the current `hard`-style positioning. The main issue is benchmark calibration: the task looks more like a medium item unless there is stronger evidence that capable models struggle for the right reasons.
