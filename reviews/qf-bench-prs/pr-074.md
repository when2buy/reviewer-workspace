## Summary
This is a readable and deterministic Black-Litterman task, but I do not think the current evidence supports it as a strong medium benchmark item. The optimization setup is standard, the outputs are heavily pinned by exact expected values, and the PR body does not provide complete validation evidence.

- Difficulty calibration: **2/5**
- Model discrimination: **2/5**

- Data realism / determinism: **4/5**

## Findings

### [MAJOR] Difficulty is likely overstated even as a medium task
The task is very cleanly specified, the outputs are heavily pinned by exact expected values in tests, and the optimization setup is standard Black-Litterman with no especially tricky edge cases. The Markowitz optimum also collapses to a corner solution (`XLK = 1.0`), which makes the optimization side easier rather than harder.

### [MAJOR] Evidence for benchmark quality is incomplete
The PR body says Oracle passes, Finance-Zero fails, and two frontier-agent runs will be added later. That is not enough for review in its current state. I want the actual evidence in the PR.

### [MAJOR] The verifier is brittle on failure
`tests/test.sh` uses the fragile `$?` pattern after the main `uvx ... pytest ...` invocation.

### [MAJOR] Hardcoding resistance is weak
The tests expose exact target values for equilibrium returns, posterior returns, portfolio returns, volatilities, and Sharpes. There are only 6 assets and one fixed dataset, so the task is easy to overfit.

### [MINOR] Instruction path naming is inconsistent with common repo style
The instruction refers to `/app/sector_etf_prices.csv`, while many tasks in this repo use `/app/data/...`.

## What is good
- The math contract is readable.
- The BL setup is deterministic.
- The data, solution, and tests are internally consistent.

## What should change
1. Add the missing empirical validation evidence to the PR body.
2. Revisit difficulty calibration.
3. Fix `tests/test.sh` reward handling.
4. Strengthen verifier design so success depends less on matching a long list of exact exposed constants.

## Verdict
**REQUEST CHANGES**
