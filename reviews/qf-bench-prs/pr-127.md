# PR #127 — crypto-funding-rate-basis-carry

## Summary
This is a solid, realistic crypto task with good domain flavor and a believable medium difficulty target. The main problems are benchmark hygiene, not task idea: the PR is not cleanly scoped, and the verifier leaks so much of the oracle that an agent can likely hardcode most of the answer.

## Scores
- Task contract / instruction: **4/5**
- Verifier robustness: **1/5**
- Difficulty calibration: **3/5**
- Model discrimination: **4/5**
- Review hygiene / PR cleanliness: **1/5**
- Data realism / determinism: **4/5**

## Findings

### [CRITICAL] The PR is not cleanly scoped to a single task
PR #127 is titled and described as `crypto-funding-rate-basis-carry`, but it also adds a full unrelated task:
- `tasks/cme-hdd-option-pricing/*`

That should be split into its own PR. Mixing two benchmark tasks in one review unit makes provenance, scoring, and merge decisions much noisier than they need to be.

### [CRITICAL] The verifier leaks an almost complete oracle
`tasks/crypto-funding-rate-basis-carry/tests/test_outputs.py` pins a very large fraction of the final numeric outputs directly:
- exact observation count and date endpoints
- many descriptive stats
- regime means, positivity rates, and OU kappas
- full-sample OU parameters
- MC moments and percentiles
- multiple output-file schemas and selected exact values

This makes the task much easier to game by emitting precomputed outputs rather than solving the analysis.

### [MINOR] The reference solution ignores `cvar_confidence` as an independent parameter
In `solution/solve.py`, `mc_basis_carry(..., var_conf, cvar_conf)` accepts both thresholds, but the CVaR calculation is effectively taken from the VaR cutoff and does not separately use `cvar_conf`. With current params both are `0.95`, so this does not show up in tests, but it is still a spec/oracle mismatch.

## What should change
1. Split `tasks/cme-hdd-option-pricing/*` into a separate PR.
2. Rework `tests/test_outputs.py` so it checks fewer visible pinned constants and more derived invariants or hidden-reference comparisons.
3. Reduce direct answer leakage, especially for OU and Monte Carlo outputs.
4. Make the reference solution respect `cvar_confidence` independently, or remove that parameter from the task contract if it is intentionally fixed.

## Verdict
**REQUEST CHANGES**
