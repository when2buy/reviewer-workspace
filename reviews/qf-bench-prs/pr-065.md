### What This PR Does (Plain Language)
This PR adds a fixed-income benchmark task where an agent must price and analyze a Treasury-bond portfolio, including accrued interest, dirty price, yield, duration, convexity, DV01, z-spread, key-rate durations, and scenario PnL. In plain terms, the agent has to turn bond reference data and a zero curve into a full portfolio risk report.

Review focus: the important questions here are contract alignment and financial correctness. For a bond-analytics task, instruction / oracle / verifier mismatches are especially damaging because they can make a numerically correct implementation fail for the wrong reason.

### A. Structural Completeness — 8/10
The task idea is strong. The fixed-income workflow is realistic, and the PR clearly aims at a meaningful multi-step analytics task.

### B. Task Contract & Determinism — 4/10
**[MAJOR] `instruction.md`, `solution/solve.sh`, and `tests/test_outputs.py` disagree on required `solution.json` keys**  
Files: `tasks/bond-portfolio-analytics/instruction.md`, `tasks/bond-portfolio-analytics/solution/solve.sh`, `tasks/bond-portfolio-analytics/tests/test_outputs.py`

The instruction describes one set of intermediate keys, while the tests require a different set, and the oracle writes yet another partially overlapping set. That is a direct contract failure.

Suggested fix: make the public instruction, oracle output, and verifier assertions agree exactly on the required key names.

**[MINOR] The instruction over-specifies numerical method choice without clear verifier justification**  
File: `tasks/bond-portfolio-analytics/instruction.md`

The task appears to prescribe Newton's method explicitly, while the oracle reportedly uses a hybrid approach. If exact method choice is not essential to correctness, the task should specify the required result, not force one solver style.

Suggested fix: either relax the method requirement or enforce it consistently.

### C. Reasoning & Domain Knowledge — 8/10
The task covers real bond analytics rather than toy arithmetic. Day-count handling, z-spread convention consistency, key-rate durations, and portfolio aggregation all make this a meaningful benchmark item.

### D. Evaluation Criteria & Grading Reliability — 4/10
**[MAJOR] Required outputs are under-validated**  
Files: `tasks/bond-portfolio-analytics/instruction.md`, `tasks/bond-portfolio-analytics/tests/test_outputs.py`

The instruction requires outputs such as per-bond `mac_duration` and a semantically meaningful `cashflows.csv`, but the verifier reportedly does not actually validate all of that content. That weakens trust in the grade.

Suggested fix: add assertions for all required outputs, especially fields the instruction explicitly promises.

**[MINOR] Scenario-PnL test documentation is internally inconsistent**  
File: `tasks/bond-portfolio-analytics/tests/test_outputs.py`

The scenario PnL test docstring refers to a +50 bp shift, while the task parameters use `shift_bps = 100`.

Suggested fix: correct the test documentation so it matches the actual parameterization.

### Summary
This is a worthwhile fixed-income task, but the contract is not aligned tightly enough to approve as-is. The main blockers are straightforward: the instruction, oracle, and verifier disagree on required outputs, and some promised outputs are not actually graded.

| Priority | Action |
| --- | --- |

| 🔴 Must fix | Validate all required outputs that the instruction promises |
| 🟠 Should fix | Correct the scenario-PnL documentation mismatch |
| 🟠 Should fix | Relax or justify the explicit Newton-method requirement |

### Verdict
REQUEST CHANGES

The task idea is good, but the grading contract is not aligned well enough for merge.
