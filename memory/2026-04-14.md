## QFBench review skill requirements

Steve asked to consolidate prior QFBench review preferences into a dedicated project-specific skill.

Key requirements captured from workspace docs and prior review artifacts:
- Start reviews with a plain-language explanation of what the PR/task does, assuming the reader may not know the domain.
- Include a "What I did to review this" section listing files inspected, code executed, checks performed, and any sub-agents used.
- Encourage actual execution and verification, not just diff reading.
- Focus QFBench review on benchmark integrity: instruction-test alignment, verifier leakage, oracle robustness, difficulty calibration, anti-cheat properties, skill leakage, and PR scope hygiene.
- Use stable verdicts: APPROVE, REQUEST CHANGES, NEEDS DISCUSSION.
- GitHub PR reviews should be written in English.
